## Start here (for a human)
1. Read `docs/VISION.md`, `docs/FEASIBILITY.md` and `docs/ROADMAP.md`.
2. Open this folder as the Codex workspace. Paste `PROMPT_01_MASTER.md` into Codex. Keep `AGENTS.md` in the repository root.
3. `addon/AzerothKart/` is the addon folder to copy into the Forever `Interface/AddOns/` folder. Verify client flavor and TOC in `docs/CLIENT_API.md` first. The [developer install helper](docs/RELEASE.md#developer-install) supports a no-write preview, verified backups and repeat installs; use it only for an authorized deployment.
4. After an update, `/reload` (fully restart the client when the update adds files), then open `/akart` or `/azerothkart`. The main menu opens: choose **Single Player**, pick **Mirage Raceway**, **Test Oval** or the Capital Cities Cup's **Stormwind City Circuit**, **Ironforge Grand Prix** **Orgrimmar Canyon Rush**, **Darnassus Canopy Run** or **Undercity Slime Circuit**, pick a kart, then deliberately click **Race!** ([front-end flow](docs/art/ui/front-end.md); its client appearance is NOT RUN). After **Close results**, the bar's **Track** button switches maps while stopped and **Start Race** begins again. The chosen track, kart and settings are remembered; Test Oval is the default until a track is chosen. Changing maps clears the prior local run and timing sample; a failed texture load keeps the existing track and result. A 3–2–1 countdown holds the kart at spawn; held controls begin driving after GO. W/Up throttle, S/Down brake/reverse, A/D or Left/Right steer. Hold Space while turning on the road at speed 90+ to drift; Tier 1 takes 0.5 seconds of charging, Tier 2 takes 1 second. Drift steering turns more gently than ordinary steering. Brief steering corrections retain charge for up to 0.2 seconds without adding more; a valid opposite turn resumes it. Release Space on the road at speed 90+ without braking to spend a charged boost, including during that correction pause. The charge meter reaches Tier 1 halfway and Tier 2 when full, then shows remaining boost on a shared 0.8-second scale. Blue indicates charging, gold/pink a ready tier, cyan boosting; text labels name each phase and the surface. Grass (rough salt on Mirage) slows the kart and clears drift/boost; wall contact keeps useful sliding motion and held steering; blocked frontal impacts still stop, and parking turns are faster. Incidental mouse clicks and unassigned keys keep the run going; unassigned keys are consumed during capture. **Stop**, Escape or Close ends the run; Start/Restart begins a fresh one. Enter or Numpad Enter deliberately ends capture for chat. Actual text focus, an available application-focus loss check, hiding or leaving the world also stops capture. Combat closes the window and records an interruption. On build 70450, the observed application-focus getters are absent; held-key Alt-Tab behavior remains pending.
5. Record *actual* results of keyboard focus, rendering, frametimes, and combat interrupts in `docs/PROGRESS.md`. An addon loaded successfully does not establish multiplayer feasibility.
6. For the camera slice, use `python scripts/test_lua.py --runtime lua51 --tests presentation ui`; it parses all Lua and runs the selected checks. Use `python scripts/validate_project.py` for relevant structural changes. The full dual-runtime suite is reserved for a failure/risk or integration checkpoint. Install the pinned dependency with `python -m pip install --target local-artifacts/python-deps -r requirements-dev.txt`. See [the test plan](docs/TEST_PLAN.md) for broader checks.
7. After a stopped drive, run `/akart probe` (or click **Print Probe**, shown with Settings → **Show developer info**) to report frame/tick/drop counts, active frame duration, executed simulation duration, callback cadence and explicit UI object counts. Start/Stop refresh the HUD immediately; stopped timing metrics stay frozen until a new Start. Follow [the client checklist](tests/MANUAL_CLIENT_CHECKLIST.md); live tests and network measurements remain pending.
8. Optional profiling: while stopped, `/akart perf on` arms the next Start for up to 600 active updates. After stopping, `/akart perf` prints averages/maxima for simulation and render/HUD elapsed milliseconds; `/akart perf off` disables collection. It defaults off. These instrumented timer spans include probe overhead and are not exclusive CPU or GPU measurements; see [scope and manual checks](tests/MANUAL_CLIENT_CHECKLIST.md).

## Core commitments
- Multiplayer is part of the product vision but **must pass real-client network feasibility gates** before we claim a simultaneous eight-player racer is achievable.
- Pure Lua math and simulation are independent of WoW UI and network code.
- No protected-action automation, combat advantage, bypass of secret values, external control software, or in-game money/stakes.
- Solo mechanics support the multiplayer release target. If the real-client transport gate fails, review scope with the owner; ghosts/time trials are deferred, not an automatic release substitute.
- Original art and Warcraft III game/community assets are accepted sources under [ADR 0009](docs/adr/0009-warcraft-iii-asset-reuse.md), with per-file provenance, source terms and credits. Other commercial racing assets remain excluded. Warcraft fan-addon context does not imply affiliation or a general redistribution grant.
- No misleading "tested" claims. Tests must be recorded with evidence, client build, and environment.

## Important limitations of this starting package
The included Lua is a **local solo driving prototype** with progressive keyboard steering, deterministic drift charge, release boosts, grass slowdown, perimeter-wall sliding, interpolated kart presentation, a drift/boost meter and three-lap runs through ordered directional checkpoints. A deterministic 3–2–1/GO countdown precedes each run. It has no saved race records, weapons, production-ready content set, AI or production multiplayer. The bounded experimental two-player mode is described above. Track/kart/settings preferences are implemented in the reviewed front end; persistence in the combined client build remains NOT RUN. The opt-in network experiment is a diagnostic, not a live race. Physics compatibility is version8 (wall sliding and faster parking turns; high-speed drift retained): ordinary turns still build over eight ticks from center, release centers over four, and a full reversal centers before building the opposite turn. Drift yaw is gentler, charge tiers arrive at 30/60 ticks, and held Space preserves charge through up to twelve correction ticks. The owner reported difficult drift charging with the prior handling; version-6 handling, moving camera/interpolation, countdown and finish flow remain **NOT RUN** in the client. The stopped closer-camera layout loaded successfully; exact focused results belong in `docs/PROGRESS.md`. Prior M0 tests covered a 10,000-tick seeded tape, bounded profiling and mocked input/combat lifecycle. Live checks confirmed build `1.60.1.70450`, interface `16001`, project ID `18`, `Camelot` TOC and basic driving/release behavior. Simultaneous W/Up remains skipped at the owner's request. Combat closes the window and records "Game interrupted by combat", retaining actual partial solo progress (ADR 0006); no remote standings are invented.

The current candidate uses 79 explicit UI frames, 166 textures and 81 font strings in an 856×762 window, including the [front-end menus, race HUD and results dialog](docs/art/ui/front-end.md) and the Capital Cities Cup's track list and eight pooled gate strips (65/160/79 before the cup; 11/151/13 for the window without the menus). They include the stopped-only [Kart button](docs/art/karts/roster.md#kart-button) and 38 pooled [drift and boost effect](docs/art/effects/drift-boost.md) textures: tier-coloured sparks, tyre dust, and exhaust flames and soot (client appearance NOT RUN). Pooled gate strips (eight, one per gate of the current track) highlight the next gate and retain passed gates; the checkpoint text also names the next target. Drive counterclockwise from the right-hand start: North, West, South, then Start. Each accepted circuit awards one lap. The lap HUD shows `Best: --` until a completed lap, then the fastest completed duration and its lap number. Equal times keep the earlier lap; an incomplete lap never replaces it. On the third lap the run stops at the finish tick, releases controls and shows total, last-lap and current-run best completed-lap times in a summary with a Restart button. Stopping early retains actual partial progress; combat labels the interruption and closes the window. Reopening keeps the frozen summary and best lap; rejected Starts preserve them. A successful fresh Start or Restart clears both. The best is kept only within this run, with no saved personal record across runs. Times come from integer simulation ticks at 1/60 second, beginning at GO and including acceleration; the 180 countdown ticks, dropped callback time and stopped time are excluded. Physics/loop/probe counters include the countdown. The center cue shows GO for the first 60 racing ticks. A hitch can extend countdown wall time because dropped ticks never skip countdown steps. Stopping during countdown freezes zero race elapsed time; Restart begins a fresh countdown. These are local solo results, with no competitive route-validation guarantee. See [the gate and timing rules](docs/TRACKS.md).

Mirage Raceway version 1 is selectable while stopped. Its closed 16-vertex centerline has a 112-unit capsule-union road, perimeter walls, a north-facing start and four directional gates. The original `Assets/Tracks/SaltFlats/Background.tga` (scenery v1) is painted against that geometry, not cropped from the concept board; simulation never reads painted pixels. The layout generator exports matching [JSON](docs/art/mirage-layout.json) and [SVG](docs/art/mirage-layout.svg). In play, a north-up camera follows the interpolated kart pose at scale 1.5, with 60 world units of heading look-ahead and a view clamped to the map edges. It fills the 800×480 canvas with a cropped view of the map; the kart is 25.5×46.5 canvas units and the road is 168 wide. Positions, sprite dimensions and clipped gate/wall strips share that transform. Test Oval keeps its fixed overview. The background is loaded on deliberate selection or first-open saved-track restoration and reused; a load failure retains the existing working map. The owner's screenshot confirmed the earlier whole-map TGA; a later [stopped client check](docs/evidence/2026-10-20-mirage-camera-static.md) confirmed the closer crop, larger kart, aligned Start strip and clipped West strip on build 70450, with counts 9/111/13. Camera motion, edge behavior and handling remain **NOT RUN**. The default kart is the Goblin Mortar Trike: a sheet of 64 three-quarter-view headings rendered from a Warcraft III model, shown unrotated at the nearest heading. It is loaded once at creation, with the primitive as automatic fallback. While stopped, the Kart button cycles six cosmetic karts that drive identically; a choice loads its art with the same guards, a refusal keeps the current kart, and the choice is not saved. The owner's [in-game screenshot](docs/evidence/2026-10-20-mirage-scenery-owner-check.md) showed the earlier Goblin Drag Car sprite and scenery v1 at the Mirage start, and he later [approved the trike and the scenery shadow pass](docs/evidence/2026-10-20-trike-and-shadows-owner-approval.md); itemized moving checks remain **NOT RUN**. See [the short probe](docs/FEASIBILITY.md#mirage-blockout-first-load-probe).

The meter updates from actual simulation ticks and needs no new frames. Its labels and the existing drift/surface text provide feedback beyond color. Active kart rendering blends the previous and current 60 Hz positions and turns through the shortest heading arc, including frames without a simulation step. This adds at most one fixed step of visual delay; checkpoint progress uses actual fixed-step coordinates. Stop shows the exact final pose and freezes the meter with `Last drive` feedback; Start resets it. See `docs/PROGRESS.md` for the next build task. Deferred scale, long profiling and repeated manual matrices do not block local development.
