# Azeroth Kart — top-down arcade racing inside WoW Forever

**Status:** M1 local mechanics development; M0 acceptance remains open. The owner requested build-first work with focused validation ([ADR 0007](docs/adr/0007-build-first-development.md)).
**Vision:** A polished, responsive top-down 2D kart racer wholly inside a movable World of Warcraft addon window, inspired by approachable arcade racing, with original presentation and Warcraft-flavored humor.

**First production map:** Mirage Raceway on the dry Shimmering Flats, with recognizable Warcraft III-like machines and riders. The [map/vehicle brief](docs/art/MIRAGE_RACEWAY.md), [asset-source shortlist](docs/art/ASSET_SOURCES.md) and [concept board](docs/art/concepts/mirage-raceway-direction-v1.png) record the owner's direction. Precomposed background/foreground art with separate geometry is planned; the installed playable build remains Test Oval.

## Start here (for a human)
1. Read `docs/VISION.md`, `docs/FEASIBILITY.md` and `docs/ROADMAP.md`.
2. Open this folder as the Codex workspace. Paste `PROMPT_01_MASTER.md` into Codex. Keep `AGENTS.md` in the repository root.
3. `addon/AzerothKart/` is the addon folder to copy into the Forever `Interface/AddOns/` folder. Verify client flavor and TOC in `docs/CLIENT_API.md` first. The [developer install helper](docs/RELEASE.md#developer-install) supports a no-write preview, verified backups and repeat installs; use it only for an authorized deployment.
4. Enable addon in the game; type `/akart` or `/azerothkart`. Click `Start Test Drive` deliberately. A 3–2–1 countdown holds the kart at spawn; held controls begin driving after GO. W/Up throttle, S/Down brake/reverse, A/D or Left/Right steer. Hold Space while turning on the road at speed 90+ to drift; release Space while continuing the turn to spend a charged boost. The charge meter reaches Tier 1 halfway and Tier 2 when full, then shows remaining boost on a shared 0.8-second scale. Blue indicates charging, gold/pink a ready tier, cyan boosting; text labels name each phase and the surface. Grass slows the kart and clears drift/boost; the gray perimeter wall scrubs speed while allowing sliding along it. Escape, another key, any mouse click, Stop, Close or losing focus stops capture; click Start to restart. Combat closes the window and records an interruption.
5. Record *actual* results of keyboard focus, rendering, frametimes, and combat interrupts in `docs/PROGRESS.md`. An addon loaded successfully does not establish multiplayer feasibility.
6. For the current-run best-lap slice, use `python scripts/test_lua.py --runtime lua51 --tests laps race ui`; it parses all Lua and runs the selected checks. Use `python scripts/validate_project.py` for relevant structural changes. The full dual-runtime suite is reserved for a failure/risk or integration checkpoint. Install the pinned dependency with `python -m pip install --target local-artifacts/python-deps -r requirements-dev.txt`. See [the test plan](docs/TEST_PLAN.md) for broader checks.
7. After a stopped drive, run `/akart probe` or click **Print Probe** to report frame/tick/drop counts, active frame duration, executed simulation duration, callback cadence and explicit UI object counts. Start/Stop refresh the HUD immediately; stopped timing metrics stay frozen until a new Start. Follow [the client checklist](tests/MANUAL_CLIENT_CHECKLIST.md); live tests and network measurements remain pending.
8. Optional profiling: while stopped, `/akart perf on` arms the next Start for up to 600 active updates. After stopping, `/akart perf` prints averages/maxima for simulation and render/HUD elapsed milliseconds; `/akart perf off` disables collection. It defaults off. These instrumented timer spans include probe overhead and are not exclusive CPU or GPU measurements; see [scope and manual checks](tests/MANUAL_CLIENT_CHECKLIST.md).

## Core commitments
- Multiplayer is part of the product vision but **must pass real-client network feasibility gates** before we claim a simultaneous eight-player racer is achievable.
- Pure Lua math and simulation are independent of WoW UI and network code.
- No protected-action automation, combat advantage, bypass of secret values, external control software, or in-game money/stakes.
- Local solo/time-trial remains valuable and shippable even if realtime networking is not.
- The original project's UI, assets, and code must not copy Nintendo/Activision/Blizzard art, branding, music or tracks. Warcraft setting is fan-addon context, not affiliation.
- No misleading "tested" claims. Tests must be recorded with evidence, client build, and environment.

## Important limitations of this starting package
The included Lua is a **local solo driving prototype** with progressive keyboard steering, deterministic drift charge, release boosts, grass slowdown, perimeter-wall sliding, interpolated kart presentation, a drift/boost meter and three-lap runs through ordered directional checkpoints. A deterministic 3–2–1/GO countdown precedes each run. It has no saved records, weapons, production assets, AI or multiplayer. Physics compatibility stays version 5: turns build over eight ticks from center, release centers over four, and a full reversal centers before building the opposite turn. Human handling, the new layout, interpolation, meter, countdown and finish flow are **NOT RUN** in the client; exact focused offline results belong in `docs/PROGRESS.md`. Prior M0 tests covered a 10,000-tick seeded tape, bounded profiling and mocked input/combat lifecycle. Live checks confirmed build `1.60.1.70450`, interface `16001`, project ID `18`, `Camelot` TOC and basic driving/release behavior. Simultaneous W/Up remains skipped at the owner's request. Combat closes the window and records "Game interrupted by combat", retaining actual partial solo progress (ADR 0006); no remote standings are invented.

The current source uses eight explicit UI frames, 110 textures and thirteen font strings in an 856×762 window. Four pooled gate strips highlight the next gate and retain passed gates; the checkpoint text also names the next target. Drive counterclockwise from the right-hand start: North, West, South, then Start. Each accepted circuit awards one lap. The lap HUD shows `Best: --` until a completed lap, then the fastest completed duration and its lap number. Equal times keep the earlier lap; an incomplete lap never replaces it. On the third lap the run stops at the finish tick, releases controls and shows total, last-lap and current-run best completed-lap times in a summary with a Restart button. Stopping early retains actual partial progress; combat labels the interruption and closes the window. Reopening keeps the frozen summary and best lap; rejected Starts preserve them. A successful fresh Start or Restart clears both. The best is kept only within this run, with no saved personal record across runs. Times come from integer simulation ticks at 1/60 second, beginning at GO and including acceleration; the 180 countdown ticks, dropped callback time and stopped time are excluded. Physics/loop/probe counters include the countdown. The center cue shows GO for the first 60 racing ticks. A hitch can extend countdown wall time because dropped ticks never skip countdown steps. Stopping during countdown freezes zero race elapsed time; Restart begins a fresh countdown. These are local solo results, with no competitive route-validation guarantee. See [the gate and timing rules](docs/TRACKS.md).

The meter updates from actual simulation ticks and needs no new frames. Its labels and the existing drift/surface text provide feedback beyond color. Active kart rendering blends the previous and current 60 Hz positions and turns through the shortest heading arc, including frames without a simulation step. This adds at most one fixed step of visual delay; checkpoint progress uses actual fixed-step coordinates. Stop shows the exact final pose and freezes the meter with `Last drive` feedback; Start resets it. See `docs/PROGRESS.md` for the next build task. Deferred scale, long profiling and repeated manual matrices do not block local development.

This directory is the Git checkout linked to [PhilForever/AzerothKart](https://github.com/PhilForever/AzerothKart). Local commits preserve the original pack and focused M0 changes. Explicit grass priority and creation-only band settings now remove the seams; normal reload and read-only checks verified the installed fix with counts 6/99/3.
