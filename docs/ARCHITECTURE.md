# Technical architecture

For implemented signatures, state fields and the Codex/Claude boundary, use [API_CONTRACTS.md](API_CONTRACTS.md) and [AGENTS.md](../AGENTS.md). The system diagram includes future components; it is not evidence of a separate Renderer/GameSession/network API. The current Codex slice adds a standalone transport experiment; race replication remains unimplemented. Test Oval solids and Mirage/Claude rendering remain independent.

## System boundaries

```
User input (WoW UI events)
        |
        v
 InputAdapter -> InputSample (five booleans per fixed tick)
        |                         |
        v                         v
 UIController/Scene        Pure Simulation (Physics/Track/Race/Items/PRNG)
        |                         |
        +<------ Immutable-ish render state / events
        |
 Renderer (pooled Texture/FontString objects, HUD and audio)

Optional multiplayer (behind measured gate):
 TransportAdapter -> ProtocolCodec -> Session/RaceAuthority -> state ingest
                               -> replay/anti-corruption checks
SavedVariables -> Schema/Migrations -> settings/personal-bests/ghosts
```

## Layering
- `Simulation`: math data only; pure-ish tick(state, input, track, parameters) -> new state/events. No game globals.
- `Track`: analytical/collision world, checkpoint gates, item/hazard spawn coordinates. Data-driven; explicit track version + checksum/hash for multiplayer and replays.
- `Race`: current pure fixed three-lap solo lifecycle (countdown/running/finished/stopped/interrupted) around Laps; other race modes remain future work.
- `Checkpoints`: pure local sequence progress over ordered directional Track gates.
- `Laps`: pure repeatable practice laps and integer tick timing around Checkpoints; no countdown, fixed race length or winner lifecycle.
- `GameSession`: game mode, seed, participants, tick authority and reproducible event log.
- `Input`: front-end state sampling; clears stuck keys on focus loss/combat; keybind remapping requires API tests.
- `Renderer`: world-to-canvas transform; viewport/UI scale; textures from fixed pool; minimap optional.
- `Network`: transport rate budget, codec, protocol state machine, ACK/retry/recovery; not used by simulation tests.
- `Persistence`: schema v1 and migration; never serialize live per-frame state excessively.
- `Presentation`: pure render-pose interpolation, uniform viewport/camera mapping, clipped rectangle projection and scalar HUD mapping; proposed scene navigation remains a separate future responsibility.
- `Diagnostics`: opt-in perf/FPS statistics, protocol rate metrics, error logs, feature gates.

## API interaction restrictions
Current WoW API calls live in `UI`, `Core` and the explicitly armed `TransportProbe` experiment. Pure modules, including `NetworkProbe`, do not call them. Production synchronization is still proposed; the probe neither reads nor writes vehicle/race state. No math library calls UI setters. Do not call secure/protected APIs or rely on secret-value readback. No special treatment of combat information is needed.

## Simulation clock
- Fixed dt = 1/60s; `OnUpdate` adds elapsed; execute at most 5 catch-up iterations/frame, then bound accumulator and record dropped simulation time.
- The simulation input sample for each tick is derived from current key state, not collected as raw frames.
- Active rendering interpolates previous/current positions using `clock.accumulator / clock.dt` and shortest-arc heading. This introduces at most one fixed step of visual delay, including frames without a simulation step. Start/Create and Stop draw the exact current pose; inactive updates and reopening retain it. Do not mutate physics through UI animation.
- Stop on focus loss/reload. Combat ends the game, closes the window and records an interrupted result once (ADR 0006); no automatic resume. Race results will freeze actual current standings when that engine exists. Anti-cheat timestamps cannot rely solely on mutable system time.

## Multiplayer architecture decision gates
- First local solo gameplay, then `NetworkProbe`, then synchronous lobby/ready/countdown without live karts.
- If capacity acceptable: host-authoritative room/session with locally predicted self kart and other-kart interpolation, measured bounded update cadence and snapshots; no naïve per-frame replication. Host may cheat or leave; communicate limitations.
- If not: asynchronous shared ghost challenges and personal bests, maintaining original modular gameplay.
- No eventual-consistency conflict should invent a race winner; if result cannot be verified, label "unverified".

## Visual performance budget
- Pool all kart/player sprite objects and HUD elements. No `CreateFrame`/`CreateTexture` per physics tick. No chat prints during motion.
- Data tables per tick are bounded and reused if Lua GC spikes; profile first, optimize second.
- For the first production track, prefer one precomposed background and optional foreground, plus pooled sprites for vehicles, interactive props and VFX. Use no ripped assets.

The Mirage blockout renderer uses one original precomposed `Assets/Tracks/SaltFlats/Background.tga`, keeping collision/surfaces/gates/spawns in independent deterministic Track data. A stopped-state Track button selects Test Oval or Mirage; Test Oval remains the default after reload. Selection loads the background through a guarded file-texture call before committing a map change. Failure leaves the previous track, run/result and timing sample intact. A successful change resets those local samples; the loaded texture is reused on later selections and Starts. The original 96 oval Texture regions remain pooled and are hidden on Mirage. No tick creates an object or loads a texture.

Mirage uses a north-up follow camera at uniform scale 1.5 across the existing 800×480 canvas. Camera focus is the interpolated kart pose plus 60 world units along its heading, clamped so the view stays within the 1024-square world. A cropped UV rectangle samples the single background; world Y is inverted once for texture UVs. Kart, gates and perimeter strips share the camera's position and dimension transform, and gate/wall rectangles are manually clipped to the canvas using the existing pooled regions. Stop renders the exact terminal pose and camera. Test Oval retains its fixed overview. The camera changes presentation only; no physics or checkpoint coordinate is transformed before simulation.

Optional foreground/preview layers and further vehicle sprites are future work. The first, the original [Goblin Drag Car](art/karts/goblin-drag-car.md), reuses the single kart Texture: it is loaded once at creation, tinted with vertex colors and falls back to the primitive if loading fails. Editable PNG/source art stays outside runtime. Strict overhead north-facing sprites can rotate; angled three-quarter artwork requires directional frames. Aircraft initially share ground collision with cosmetic hover and separate shadows. The owner's screenshot establishes the earlier whole-map background load/orientation; a separate stopped build-70450 check confirmed the close UV crop, larger kart and Start/West strip alignment/clipping with counts 9/111/13. Camera motion/edges, transparent sprite alpha and new rotation/pivot checks are **NOT RUN**. No rendering-performance claim follows from offline integration. See [ASSETS.md](ASSETS.md), [the map brief](art/MIRAGE_RACEWAY.md) and [ADR 0008](adr/0008-mirage-raceway-art-direction.md).

## Public module APIs (implemented unless marked future)
- `Physics.new(track)` -> state
- `Physics.step(state, heldInputs, dt, track)` -> new state only; contact feedback is in `impacts` and `surface`, with no separate flags/event return
- Current `Track.isDrivable(x, y)` -> boolean; `Track.crossesGate(previous, current, gate)` -> boolean
- Current `MirageRaceway.new(crossesGate)` -> independent Mirage track instance; `Presentation.fitViewport` -> overview, `.cameraViewport` -> bounded close view, `.follow` -> updates its reusable offsets from an injected pose, `.project`/`.unproject` -> uniform world/canvas mapping, `.texCoords` -> background UV crop, `.clipRect` -> visible projected rectangle or nil
- Current `Checkpoints.new(track, tick)` -> progress; `Checkpoints.step(progress, previous, current, track)` -> progress
- Current `Laps.new(track, Checkpoints, tick)` -> laps; `Laps.step(laps, previous, current, track, Checkpoints)` -> laps
- Current `Race.new(track, Checkpoints, Laps, tick)` -> race; `Race.step(race, previous, current, track, Checkpoints, Laps)` -> race; `Race.stop(race, reason, interrupted)` -> race
- Implemented experiment only: `NetworkProbe.encode/decode` uses a compact bounded DATA/ACK envelope; production `Protocol.encode(event)/decode(text)` remains future work.
- Future: `Transport.send(session,msg,target)` with queue budget; measurements/architecture remain gated
- Future: `Replay.record(inputs,seed,trackHash)` and `Replay.play(...)`; no gameplay replay API exists

## Source map

An interrupted M0 drive keeps its terminal reason through repeated Close/toggle/hide/reopen. Rejected Start attempts show their refusal alongside the retained interruption note; they do not replace the result, state or timing sample. A successful fresh Start clears the note/result. This implements ADR 0006 using the existing UI objects, with offline regression coverage; the extended client sequence remains pending.

Combat-start events also hide a shown inactive window, including a completed sample or retained result. This path preserves the stopped clock/state/HUD/reason and emits no new interrupted-drive announcement. It handles events before the active-capture guard, safely ignoring combat before UI creation. Inactive OnUpdate remains idle, allowing deliberate combat-time reopen for note/Start-refusal inspection; combat ending never reopens or resumes the drive. This follow-up is tested offline, installed and loaded; actual combat verification remains deferred after the Oct19 stopped-window finding.

Current local M1: `Track.lua` (analytical road, surfaces, wall constraints and directional gates), `MirageRaceway.lua` (pure independent production-map blockout factory), `Physics.lua` (version 7 swept Oval solids with retained v6 progressive steering, correction-tolerant drift, boost and grass response), `Input.lua` (physical held keys including Space, reused semantic samples), `Loop.lua` (fixed-step clock, cumulative elapsed and drop counters), `Performance.lua` (bounded scalar aggregates of injected timestamps), `Presentation.lua` (pure interpolation and meter mapping), `Checkpoints.lua` (pure ordered local gate progress), `Laps.lua` (pure repeated circuits and tick timing), `Race.lua` (pure fixed-length solo outcome), `UI.lua` (client adapter/presentation and stopped-state map selection), `Core.lua` (bootstrap/events/minimal schema marker). Both TOCs retain that sequence with pure `NetworkProbe` and guarded `TransportProbe` inserted between UI and Core, for fourteen modules. The adapter reuses Core's bootstrap frame, leaves startup unsubscribed/inactive and installs its bounded update/event work only on explicit arm. It does not change the 9/113/13 UI pool or driving callbacks. `UI.SelectTrack` accepts `test_oval` or `mirage_raceway` while stopped and uses that track consistently for physics, race progress and rendering. Pure modules optionally register into the explicit addon namespace passed by WoW and return their module for offline imports; they do not access `_G` or game APIs. Core alone exports `_G.AzerothKart` for manual diagnostics. M0/M1/M3 acceptance remains open; [ADR 0007](adr/0007-build-first-development.md) allows local mechanics development while long manual checks are deferred.

`MirageRaceway.new(crossesGate)` injects the finite directional crossing predicate rather than reading the addon namespace. Version 1 defines a 1024×1024 world, a closed 16-vertex centerline with road radius 56 (112 wide), an 18-unit perimeter inset, north-facing spawn (700,360) and North/West/South/Start gates. Its rough salt uses the existing grass mechanic; the current physics compatibility is v7, retaining v6 handling. `Presentation.fitViewport/project/unproject` retain aspect with one uniform scale and offsets. The authoring overview fits 1024×1024 into 800×480 at scale 0.46875 and offset (160,0); Mirage play instead uses the closer scale-1.5 follow camera described above. The developer layout generator reads the actual Lua factory and Presentation helpers through Lupa, writes JSON plus an unsmoothed round-stroke SVG, and inverts Y once for SVG display. The runtime background is a separate deterministic geometry-derived blockout, not a crop of that guide or the concept board. Offline integration does not establish client camera behavior, map handling or competitive route validation.

Checkpoint/lap progress is independent of physics compatibility version 7. After each actual fixed physics step, UI passes previous/current simulation coordinates and the new tick to pure Race, which delegates through Laps to Checkpoints. Immutable checkpoint progress stores `nextGate`, `passed`, `complete` and `lastTick`; only the expected gate can award, at most once per consecutive bounded step. Strict directional finite-segment crossing avoids awards when departing from the gate line or crossing backwards. Duplicate, stale, out-of-order or gapped tick reports return the same progress unchanged, with no automatic gap recovery. Only consecutive samples with nonfinite positions or movement over five units consume their tick without an award, allowing a following valid consecutive step to recover. This is local consistency, not a security guarantee or competitive route validation.

Laps stores `checkpoints`, `completedLaps`, `lapStartTick`, `currentLapTicks`, `lastLapTicks`, `bestLapTicks`, `bestLapNumber`, `lastTick` and `lastFinishTick`. In the UI run, the first lap begins at GO, including acceleration after release from the grid. Each fourth award completes exactly one lap, records its integer tick duration and rearms North at the same finish tick; the next lap starts at zero with no counted tick lost. Consecutive invalid movements advance time but not gates; rejected duplicate/older/gapped reports change neither. `bestLapTicks` and `bestLapNumber` begin nil and change only on a completed lap with a strictly smaller integer duration; ties keep the earliest lap, and incomplete laps never compete. New Laps state, including the GO reset, clears this in-memory best. Standalone Laps remains repeatable without a fixed limit. Display multiplies tick counts by the fixed step; elapsed seconds exclude dropped simulation time and stopped periods.

Race injects Checkpoints and Laps explicitly and stores status, lap progress, a three-lap target, countdown progress, start/last/finish ticks, total elapsed ticks and reason. The third accepted lap sets `finished` and its finish tick once. `Race.stop` records an actual partial stopped/interrupted result during countdown or running; every later step or stop returns the identical terminal object. The current-run best is retained in terminal/reopened results, including rejected Start attempts; only a successful fresh Start/Restart resets it. There is no saved personal best across runs, persistence, ghost or remote classification.

A new run counts down 180 fixed 60 Hz ticks: 3 at remaining 180–121, 2 at 120–61 and 1 at 60–1. UI samples actual held keys but supplies neutral physics input, retaining the spawn pose through the GO step at tick 180. GO resets the Race/Laps origin to that tick; the first held driving input applies at tick 181. Race/lap time excludes countdown, dropped time and stopped time; unified physics/loop/probe ticks include countdown. The pooled center `countdownCue` shows GO for racing ticks 0–59, hides at 60 and writes only on phase changes outside the quarter-second HUD throttle. Dropped hitch time extends countdown wall time without skipping fixed steps. Cancelling countdown retains zero race elapsed time; a successful Restart always begins a fresh 180-tick countdown.

UI reuses the start marker and three other gate textures, with cached next/passed colors. `UI.laps` aliases `UI.race.laps`, and `UI.checkpoints` aliases its checkpoint progress. The lap HUD shows completed count, current/last lap times and `Best: --` or `Best: %.2fs (lap %d)`; running status and the result summary identify the three-lap target. A preallocated summary panel and Restart button add two frames and three font strings; the countdown adds one more pooled font string. The Track button and one pooled Mirage background bring current explicit allocations to nine frames, 113 textures and thirteen font strings in the unchanged 856×762 window. Finished results show total and last-lap time; stopped/interrupted results show actual partial progress. Both summaries add a third line with the best completed lap of this run. The summary grows from 380×170 to 380×190 without new objects or APIs. Normal reopen retains the summary; a successful deliberate Start, Restart or map change resets it. The finish callback ends the fixed-step loop before another physics step, then UI releases capture, shows the exact final pose and freezes the clock. Combat closes the window and records its note once; later events preserve an already terminal outcome. Client circuit driving, countdown and summary appearance are NOT RUN.

Physics stores normalized `steering` alongside the other fourteen state fields, including the v6 correction counter `driftGraceTicks`. It approaches a held turn at 8 units/s and centers at 16 units/s, resolving reversal through center before building the opposite sign; both raw turn directions force immediate zero. New drift entry requires the progressive steering sign to agree with exactly one raw turn direction. Existing held drift pauses charge through up to twelve correction ticks; matching steering resumes it in either direction, while the thirteenth invalid tick clears charge. Brake, low speed, rough ground and wall contact cancel immediately. Wall contact resets steering; grass retains it. This adds no UI setting, object, input-capture behavior or client API dependency. Exact tuning and pending direct-play validation are recorded in [PHYSICS.md](PHYSICS.md).

`Presentation.pose(previous, current, alpha)` returns scalar x, y and heading, interpolating through the shortest heading arc without mutating either state or allocating a pose table. UI retains the actual state immediately before each fixed step, then renders between that and the latest state after catch-up. Input sampling, collision, drift, boosts, surface feedback and timing use actual simulation state; no interpolated coordinate becomes simulation input. Stop redraws the exact current pose without changing the frozen clock remainder. The renderer uses existing pooled objects and does not add per-frame chat.

Space samples a held drift intent. Physics alone owns charge, correction grace, signed slip, boost ticks and current surface; drift yaw is 0.75 of ordinary yaw and charge tiers take 30/60 valid ticks. A valid Space release can spend a retained tier during correction grace. Rendering does not award boosts or resolve collisions. `Track.isDrivable` retains the road mask, while `surfaceAt` permits island/exterior grass within an 18-unit perimeter inset and `constrainPosition` preserves tangent motion by clamping each axis. Grass gradually reduces excess speed and clears drift/boost/slip; wall contact scrubs speed once per step. Test Oval v2 adds two explicit solid rectangles and an optional `resolveMovement` sweep with conservative 18-unit clearance, bounded overlap recovery and sliding. Physics prefers this helper; Mirage retains its original constraint path with no obstacles. Two pooled ARTWORK markers display only the Oval physical rectangles. No collision event stream or new Physics field is added. Pure test tracks without those optional helpers retain the predicate fallback.

The fourth pooled font string (`driftHud`) names Road/Grass/Wall (Rough salt replaces Grass on Mirage) and charge/tier/boost state at the existing quarter-second HUD cadence and immediately on Start/Stop. Kart tint changes only when its phase changes: orange normal, blue charging, gold tier 1, pink tier 2, cyan boost. Four pooled gray strips identify the perimeter. Stop freezes mechanics and prefixes retained feedback with `Last drive`; Start resets state. No tick creates UI objects or prints chat.

`Presentation.meter(state, Physics)` returns only a fill fraction and phase. A correction pause retains the fill and tier and has a text cue; it never adds charge. Boost uses remaining ticks divided by the common 48-tick (0.8-second) capacity; shorter boosts therefore occupy less of the same scale. Grass/wall or cancelled charge maps to idle. UI draws a 300×12 meter using four textures and three font strings created once. Markers switch from Tier 1/Tier 2 to 0.4s/0.8s during boost, with a named phase caption and the existing text HUD retained. Fill follows actual ticks on active updates, without pose interpolation; unchanged phase/fill values avoid redundant setters, and zero fill is hidden. Stop freezes the meter and Start empties it. Profiling defaults off and is controlled separately by `/akart perf [on|off]`; no UI objects/settings persistence are added. While stopped, `on` validates one guarded `debugprofilestop` read and arms the next Start. A profiled Start creates a fresh scalar aggregate. The first 600 eligible active updates take three guarded readings around `Loop.advance`, then kart rendering plus the throttled HUD update; later callbacks make no profiler calls. The pure Performance module accepts timestamps in milliseconds, storing only attempt/valid/invalid counts and phase totals/maxima. Invalid, nonfinite, backwards or throwing readings consume the same attempt cap without affecting driving; failures in arithmetic validation are contained. No `debugprofilestart` reset is used. Stop/close/reopen freeze the aggregate; off retains it until a new Start. Reports are explicit, three lines, and the existing six-line `/akart probe` is unchanged.

Reported spans are advisory elapsed profiler milliseconds. They include instrumentation inside each span and omit input/focus guards, final aggregation/report formatting and native GPU work; they are not exclusive addon CPU attribution or a whole-OnUpdate benchmark. Shared timer resets can yield invalid backwards samples or occasionally plausible positive deltas that cannot be detected. A build-70450 stationary window supplied 600 valid samples and retained stopped/disarmed results; full performance acceptance remains pending. [CLIENT_API.md](CLIENT_API.md) records the generated contract, actual scoped results and remaining checks.

`Loop.advance(clock, elapsed, stepFn)` runs up to five 1/60s steps per render frame. A callback returning exactly `false` halts after that counted step; unused whole ticks are recorded as dropped time and the fractional remainder is retained. This prevents catch-up from simulating beyond a finish. `hitchFrames` depends on the incoming available tick count exceeding the five-step budget, so an ordinary finish does not invent a hitch. `clock.elapsedSeconds` sums valid elapsed values accepted by the clock. UI calls it only while driving, so the explicit probe labels this `activeFrameSeconds`; `simulatedSeconds` is `steps * dt`, and `callbackHz` is `frames / elapsedSeconds` (zero before elapsed time). These measure delivered callback time and cadence, not an independent wall clock, separately sampled whole-client FPS or addon CPU cost. `maxElapsed` records the largest accepted callback interval. Samples retain `elapsedSeconds ≈ steps * dt + droppedSeconds + accumulator` within floating-point/printed precision, including early terminal stops.

Tick input comes from `Input.sample(held, reusedOutput)`. UI sprites are created once; HUD text updates at a bounded cadence during driving and immediately at Start/Stop, so the stopped tick agrees with the probe and a fresh drive displays tick 0. The HUD's `Sample` duration is active callback time. Stop freezes every clock counter, including the fractional accumulator, without resuming simulation. Close/reopen retains that stopped sample; a deliberate Start creates a fresh clock. Probe output is explicit only, with no timed chat reports, automatic driving or additional UI objects. There is no production replay/PRNG yet. The offline seeded tape generator is test code, not a gameplay random mechanic. See PROGRESS for the next build task.
