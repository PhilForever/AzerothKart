## Scope and disposition

These screenshots establish addon `/reload` cleanup to Idle, the remaining sender's bounded ACK-deadline stop, and successful **explicit fresh-session rearming**. They do not establish a socket disconnect/full logout, automatic rejoin, persistence of the interrupted session, or measured recovery seconds. No exact client builds/interfaces, location, test UTC or reload timestamps were supplied. Earlier different-zone/ungrouped/US-beta context is not a new independent observation or a measured latency cause for these sessions.

Together with [AKT722](2026-10-21-akt722-network-window.md) and [AKT723](2026-10-21-akt723-network-window.md), this is enough to proceed with the **bounded experimental two-peer control implementation** in [ADR 0013](../adr/0013-two-player-experiment-scope.md). It is not production multiplayer, release approval or full M2 acceptance. The working pair-budget ceiling is **four aggregate API calls/s and 316 payload-plus-prefix bytes/s before overhead**: both ceilings apply, and this is a previously exercised schedule rather than a measured maximum. Simultaneous bidirectional traffic, race corrections, starts/finishes and handling still need the eventual candidate check. Approximately 700 ms RTT remains material; no numeric RTT acceptance threshold or production replication model is silently selected.

No further manual probe is requested now. The current code slice adds only a pure version-2 `RaceProtocol` encode/decode unit with separate prefix `AZKART2`; it sends nothing and implements no session handshake. The next concrete coding task is a pure `PeerSession` invite/join/ready/start state machine with duplicate and timeout tests. Replication authority, clock synchronization and movement remain proposed until candidate implementation review.
